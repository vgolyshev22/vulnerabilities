После определения версий запущенных служб был выполнен поиск известных уязвимостей для соответствующего ПО в Exploit Database.

1. vsftpd 2.3.4 — Backdoor Command Execution

На порту 21/tcp обнаружен FTP-сервер vsftpd 2.3.4. Для данной версии существует известная уязвимость, связанная с наличием вредоносного backdoor в скомпрометированной версии дистрибутива. Уязвимость позволяет получить возможность удалённого выполнения команд. Exploit-DB указывает CVE-2011-2523 и EDB-ID 17491.

Exploit-DB — vsftpd 2.3.4 Backdoor Command Execution

2. Samba 3.0.20 — Username Map Script Command Execution

На портах 139/tcp и 445/tcp работает Samba 3.0.20. Версии Samba от 3.0.20 до 3.0.25rc3 при определённой конфигурации подвержены уязвимости username map script, позволяющей удалённо выполнить произвольную команду. Exploit-DB указывает CVE-2007-2447 и EDB-ID 16320. Для эксплуатации уязвимости аутентификация не требуется.

Exploit-DB — Samba Username Map Script Command Execution

3. UnrealIRCd 3.2.8.1 — Backdoor Command Execution

На порту 6667/tcp обнаружен IRC-сервер UnrealIRCd. Версия UnrealIRCd 3.2.8.1 известна наличием скомпрометированного дистрибутива с backdoor, позволяющим удалённо выполнять команды. Уязвимость имеет идентификатор CVE-2010-2075, а соответствующий эксплойт в Exploit-DB — EDB-ID 16922.

Exploit-DB — UnrealIRCd 3.2.8.1 Backdoor Command Execution

Вывод: сканирование Metasploitable показало большое количество доступных сетевых сервисов, часть которых использует устаревшие и заведомо уязвимые версии программного обеспечения. ### Задание 2

SYN-сканирование
sudo nmap -sS 10.2.0.15

FIN-сканирование
sudo nmap -sF 10.2.0.15

Xmas-сканирование
sudo nmap -sX 10.2.0.15

UDP-сканирование
sudo nmap -sU 10.2.0.15

Во время выполнения каждого сканирования сетевой трафик записывался в Wireshark.

SYN Scan

При SYN-сканировании Nmap отправляет на проверяемый TCP-порт пакет с установленным флагом:

SYN

Если порт открыт, сервер отвечает:
Nmap → Server: SYN

Server → Nmap: SYN, ACK

Nmap → Server: RST

То есть полноценное TCP-соединение не устанавливается. Nmap получает SYN/ACK, понимает, что порт открыт, после чего сбрасывает соединение.

Если порт закрыт, сервер обычно отвечает:

Nmap → Server: SYN

Server → Nmap: RST, ACK

Таким образом, наличие SYN/ACK говорит об открытом TCP-порте, а RST — о закрытом.


FIN Scan


При FIN-сканировании Nmap отправляет TCP-пакет без предварительного установления соединения, но с установленным флагом:


FIN


То есть в Wireshark вместо обычного начала TCP-соединения через SYN наблюдаются пакеты с флагом FIN.


Для закрытого порта сервер, соответствующий поведению TCP/IP, отвечает пакетом:

RST


Для открытого порта ответ обычно отсутствует.


Поэтому Nmap делает вывод примерно следующим образом:

FIN → нет ответа → open|filtered

FIN → RST       → closed

Здесь появляется состояние open|filtered, потому что по отсутствию ответа Nmap не может однозначно определить, открыт порт или пакет просто был отброшен межсетевым экраном.


Xmas Scan


Xmas-сканирование похоже на FIN, однако отправляемый TCP-пакет содержит сразу несколько установленных флагов:


FIN

PSH

URG


Такой пакет называется Xmas packet, поскольку несколько установленных флагов условно напоминают «гирлянду».


Поведение сервера аналогично FIN-сканированию:

FIN, PSH, URG → открытый порт → обычно нет ответа


FIN, PSH, URG → закрытый порт → RST

Поэтому открытые порты Nmap также часто показывает как:


open|filtered


Главное отличие от FIN Scan, которое хорошо видно в Wireshark, заключается именно в TCP-флагах:

FIN Scan:

FIN = 1


Xmas Scan:

FIN = 1

PSH = 1

URG = 1


UDP Scan


UDP принципиально отличается от предыдущих вариантов, поскольку UDP не использует TCP-флаги и процедуру установления TCP-соединения.


Nmap отправляет UDP-датаграмму:


Nmap → Server: UDP


Если UDP-порт закрыт, сервер обычно сообщает об этом с помощью ICMP:

Server → Nmap:

ICMP Destination Unreachable

Port Unreachable

Если UDP-порт открыт, возможны два варианта: приложение возвращает UDP-ответ либо вообще ничего не отвечает.


Поэтому при отсутствии ответа Nmap часто не может однозначно определить состояние и показывает:


open|filtered


В Wireshark главное отличие UDP Scan от предыдущих режимов видно сразу: Nmap отправляет UDP-пакеты вместо TCP, а для закрытых портов можно наблюдать ответы ICMP Destination Unreachable (Port unreachable).
